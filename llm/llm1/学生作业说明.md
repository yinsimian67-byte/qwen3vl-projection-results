# 实现与实验指南

以下命令均从解压后的学生包根目录执行，适用于 Linux、Python 3.10 或 3.11 和单张 24 GB NVIDIA GPU。先在开发集（dev）完成实验和方法选择，方案冻结后再生成最终集（final）预测。必做对照、提交内容和评分规则见[学生手册](学生手册.md)。

## 1　安装环境并检查数据

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install torch==2.6.0 torchvision==0.21.0 --index-url https://download.pytorch.org/whl/cu124
python -m pip install -r requirements-locator.txt -r requirements-vlm.txt
python -c "import torch; print(torch.__version__, torch.cuda.is_available())"
python scripts/train_locator.py --feature-root data/features --data-dir data/course \
    --output-dir outputs/data_check --check-only
```

CUDA 检查应显示 `True`。A 可直接使用包内特征。运行 C 前，联网下载并校验清单锁定的两个 Qwen 权重分片，脚本默认写入配置使用的 `models/Qwen2.5-VL-3B-Instruct/`。若使用另一个可联网的电脑下载，请将下载好的整个模型目录复制到实验机相同位置。

```bash
python scripts/download_model.py --weights-only
```

| 包内路径 | 实验用途 |
| --- | --- |
| `data/course/` | train 1,500 条和 dev 200 条有标签查询，final 300 条仅含查询。每条查询保留自己的视频切片时间坐标。 |
| `data/features/` | A 的 SlowFast 视频、CLIP 视频和 CLIP 文本特征，含三个划分。 |
| `data/reference_candidates/` | C 的固定 Top-3 候选，所有组共享原始顺序和时间边界。 |
| `data/reference_full/sft_pairwise.jsonl` | C 的 1,248 对训练片段，每对含一个正片段和一个负片段。 |
| `data/reference_full/sft_pointwise.jsonl` | 将上述同一批片段拆成的 2,496 条 Yes/No 样本。 |
| `data/reference_frame_cache/` | C 的训练和评价帧，读取时使用 `--cache-only`。 |

训练对均来自 train，正例与任一真值的最大 tIoU ≥ 0.5，负例 ≤ 0.1。原训练划分中有 252 条查询缺少有效负例，因此两个微调基线共同使用剩余 1,248 条。包内两份训练清单和帧缓存已经配好，三个训练种子均使用同一份输入。

## 2　训练定位器并在 dev 评分

以下为 A0 基线。每个种子训练 40 轮，每 5 轮计算 dev 指标。训练器将该种子 dev mAP 最高的模型、候选和评分保存到对应目录。若分数并列，保留较早的检查点。

```bash
for seed in 42 2026 3407; do
  python scripts/train_locator.py --feature-root data/features --data-dir data/course \
      --epochs 40 --batch-size 32 --learning-rate 0.0001 --eval-every 5 \
      --seed "$seed" --output-dir "outputs/A0/seed$seed" || exit 1
done
```

查看 `train_log.jsonl`、`dev_best_metrics.json`、`dev_best_candidates.jsonl` 和 `model_best.pt`。在 `student_code/` 中编写 A1、自研模块关闭版和 A2，使用相同数据与训练设置。A2 从 A0 出发，将 SlowFast 输入置零，保留原输入维度。修改模型结构时，训练和导出候选都需要从本组模型构建器加载。六种可选方向及代码位置见[核心模块方法参考](核心模块方法参考.md)。

## 3　运行 C 的零样本对照

先计算参考池原排序的 dev 分数，再分别对每条候选做 Yes/No 判断（pointwise），以及对每对候选做 A/B 比较（pairwise）。保留两个结果，分别与后续同目标的微调模型比较。

```bash
python scripts/evaluate.py --ground-truth data/course/dev.jsonl \
    --predictions data/reference_candidates/dev.jsonl \
    --output outputs/metrics/reference_dev.json

for task in pointwise pairwise; do
  pred="outputs/zero/$task/dev.jsonl"
  python -m vlm.rerank --annotations data/course/dev_queries.jsonl \
      --candidates data/reference_candidates/dev.jsonl --config "configs/vlm_qlora_${task}.json" \
      --cache-only --cache-dir data/reference_frame_cache --output "$pred" || exit 1
  python scripts/evaluate.py --ground-truth data/course/dev.jsonl --predictions "$pred" \
      --reference-candidates data/reference_candidates/dev.jsonl \
      --output "outputs/metrics/zero_${task}_dev.json" || exit 1
done
```

每次推理后检查预测旁的 `.metrics.json`。dev 应覆盖 200 条查询，`complete_vlm_evaluation` 应为 `true`。若出现回退或跳过，先查看对应 `.audit.jsonl` 文件定位 qid 和错误，修复后重新推理并评分。

## 4　训练两个微调基线并比较检查点

在输出目录生成与种子匹配的配置。包内正式配置为 4-bit NF4、语言注意力 q/v 投影的 rank-8 LoRA、每个候选 4 帧、每帧像素上限 50,176。两份配置分别累积 8 条单候选样本、4 条成对样本，每次更新均处理 8 个候选片段。

```bash
python - <<'PY'
import json
from pathlib import Path
out = Path("outputs/configs")
out.mkdir(parents=True, exist_ok=True)
for task in ("pointwise", "pairwise"):
    template = json.loads(Path(f"configs/vlm_qlora_{task}.json").read_text())
    for seed in (42, 2026, 3407):
        config = dict(template, seed=seed)
        (out / f"{task}_seed{seed}.json").write_text(json.dumps(config, indent=2))
PY
```

下面的循环在一张 GPU 上顺序训练 C0-P、C0-R 的三个种子，同一训练过程在第 312、624、936 步保存适配器。每个训练用独立目录，避免覆盖。

```bash
for task in pointwise pairwise; do
  for seed in 42 2026 3407; do
    cfg="outputs/configs/${task}_seed${seed}.json"
    run="outputs/C0/$task/seed$seed"
    python -m vlm.train --config "$cfg" --train-data "data/reference_full/sft_${task}.jsonl" \
        --cache-only --cache-dir data/reference_frame_cache --output-dir "$run" || exit 1
    for step in 312 624 936; do
      pred="$run/dev_step${step}.jsonl"
      python -m vlm.rerank --annotations data/course/dev_queries.jsonl \
          --candidates data/reference_candidates/dev.jsonl --config "$cfg" \
          --adapter "$run/checkpoint-$step" --cache-only --cache-dir data/reference_frame_cache \
          --output "$pred" || exit 1
      python scripts/evaluate.py --ground-truth data/course/dev.jsonl --predictions "$pred" \
          --reference-candidates data/reference_candidates/dev.jsonl \
          --output "$run/dev_step${step}_score.json" || exit 1
    done
  done
done
```

核对每次推理的完成状态。在一种目标上加入本组 C1 方法，用相同三个种子和曝光预算完成训练。建立关闭版本时保留其余改动，包括样本分组和顺序。只有关闭后的完整条件与对应基线一致时，才可复用基线的三次结果。

## 5　冻结并生成 final 预测

每个任务分别依据 dev 结果选定方法。A 在各自种子下取最佳检查点，C 根据三个种子的平均 dev mAP 选定同一个训练步数。记录被冻结的配置、代码、数据及权重哈希。

- A 使用选定方案对应的导出入口和三个检查点，将 `--annotations` 指向 `data/course/final_queries.jsonl`，设置 `--split final`，每个种子各输出一份 JSONL。原架构基线的导出语法见下例。
- C 使用选定方案的配置和共同步数下的三个适配器，将上节重排命令的查询和候选分别换为 `data/course/final_queries.jsonl` 和 `data/reference_candidates/final.jsonl`，为每个种子指定独立输出。再运行同目标、同提示的零样本对照，省略 `--adapter`。
- 每份 final 预测应有 300 个不同 qid，每条恰有 3 个区间。检查 C 的失败、回退和跳过数均为 0。将完整预测和推理记录列入实验记录，由课程统一计算 final 成绩。汇报中的带真值案例选自 dev。填写项目见[实验记录与PPT素材模板](实验报告模板.md)。

```bash
# 示例仅适用于选定 A0 时的 seed 42。按本组冻结方案替换加载入口和权重。
python scripts/export_candidates.py --checkpoint outputs/A0/seed42/model_best.pt \
    --feature-root data/features --annotations data/course/final_queries.jsonl \
    --split final --output outputs/final/A_seed42.jsonl
```
