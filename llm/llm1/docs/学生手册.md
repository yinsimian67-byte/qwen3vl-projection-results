# QVHighlights 多模态视频定位学生手册

**每组4人｜最低算力：单张显存24GB的GPU**

## 1 需要完成什么

给定视频和一句文字描述，找出对应事件的起止时间。作业包含两个任务：

| 任务 | 输入与输出 | 本组需要完成的工作 |
| --- | --- | --- |
| A 定位器 | 视频/文本预提取特征 → 3个时间区间 | 复现基线，自己实现一个定位模块改进，并完成对照实验 |
| C 3B模型微调 | 查询和固定的3个候选片段 → 候选排序 | 比较逐候选、成对两种QLoRA目标，在其中一种目标上自己实现一个训练改进 |

每组共完成**两个自主实现模块：A一个、C一个**。可以参考论文和开源代码，但须注明来源、说明本组实现的部分。不要求提出论文级新方法；只调学习率、训练步数或LoRA rank，只换提示文字或切换现成配置，不算自主实现。

直接用包内推理代码跑微调前的零样本对照，再与同一目标微调后的结果比较。

## 2 使用哪些数据和代码

| 划分 | 查询数 | 用途 |
| --- | ---: | --- |
| train | 1,500 | 定位器训练、微调样本构造 |
| dev | 200 | 对照实验、选择方法和检查点 |
| final | 300 | 冻结方案后生成预测，统一评分 |

- 使用提供的固定清单，不自行重划或筛选评价查询。训练监督只来自train。开发集用于选择方案，最终集仅用于生成冻结模型的预测。时间均相对当前视频切片；每条查询可能有多个真实区间，须全部保留。
- A使用SlowFast、CLIP视频和CLIP文本特征，评价本组定位器产生的Top-3候选。
- C及零样本对照使用固定版本Qwen2.5-VL-3B-Instruct、统一Top-3候选池和匹配缓存。每候选固定4帧，每帧像素上限50,176；只允许改变排序，不能改边界或增删候选。
- C的必做实验直接读取包内帧缓存，运行时加`--cache-only`。若自选方法使用新训练边界，须先补齐相应缓存。
- 保留原始基线代码，在本组`student_code/`中开发。数据读取、模型加载、训练循环、缓存和评分器可以复用。

基线命令与开发入口见[实现与实验指南](学生作业说明.md)。

## 3 自主实现模块怎么选

下表是可选参考，**A、C各选一种即可，也可以提出其他符合要求的方法**。两种QLoRA目标是必做基线，不等于已经完成C的自主实现。

| 任务 | 可选方法 | 学生需要自己实现 |
| --- | --- | --- |
| A | 查询条件门控融合（推荐入门） | 根据查询生成门控参数，使视频特征随查询变化 |
| A | 视频—文本交叉注意力 | 在基线联合编码前，让视频位置显式读取相关文本信息 |
| A | 轻量残差时序卷积 | 聚合不同时间范围的邻近视频特征，加入残差路径 |
| C | 固定难度重加权（推荐入门） | 计算训练样本难度，构造权重并接入训练损失 |
| C | 由易到难的课程采样 | 根据难度分阶段改变训练样本顺序或采样分布 |
| C | 辅助排序损失 | 在原有监督之外，让同一查询的正片段得分高于负片段 |

每种方法的论文来源、实现步骤、代码接入位置和关闭方式见[核心模块方法参考](核心模块方法参考.md)。这些是实现思路，不是已经提供的学生改进代码，也不保证必然提升成绩。

## 4 必须做哪些对照

所有对照先在完整dev 200条上完成。除所研究的改动外，数据、训练预算、随机种子和推理设置保持一致。

### A：定位器

| 实验 | 内容 | 比较目的 |
| --- | --- | --- |
| A0 | 原始基线，完整CLIP＋SlowFast特征 | 确定起点 |
| A1 | 加入本组模块 | 与A0比较方法效果 |
| A2 | 在A0中将SlowFast特征置零，保持输入维度和其他设置，重新训练 | 与A0比较运动特征的贡献 |
| A-off | 从A1中去掉一个关键改动，重新训练 | 判断效果是否来自该改动；与A0完全相同可复用 |

### C：微调

| 实验 | 内容 | 比较目的 |
| --- | --- | --- |
| 零样本对照 | 现成pointwise、pairwise各运行一次，同时保留参考池原排序 | 提供两个微调目标各自的未微调对照 |
| C0-P | QLoRA逐候选相关性：回答Yes/No | 与pointwise零样本比较 |
| C0-R | QLoRA成对偏好：回答A/B | 与pairwise零样本比较，并与C0-P比较训练目标 |
| C1 | 在C0-P或C0-R上加入本组训练模块 | 与对应C0比较方法效果 |
| C-off | 从C1中去掉一个关键改动，重新训练 | 判断效果是否来自该改动；与对应C0完全相同可复用 |

**“关闭自研组件”就是去掉新增的一项改动，恢复对应基线计算，保留其余设置。** 例如新增辅助损失，关闭时令该损失权重为0；新增融合模块，关闭时恢复原融合方式。

训练相关的关闭版本须从相同初始化来源、按相同种子和预算重新训练。只有关闭后的计算、数据顺序与分组、训练预算和推理设置均与基线一致，才可复用对应基线的三次结果；否则另跑关闭版。若增加多个模块，至少单独关闭一个关键模块，保留其他改动。

## 5 训练和评价统一要求

### 训练设置

- **种子：42、2026、3407。** 所有正式训练及训练消融均跑三次；仅用于排错的小运行除外。确定性零样本对照每种设置一次；若采用随机推理，则匹配对照也用三个种子。
- **A：** 默认40轮、batch 32、学习率1e-4，每5轮评价dev。研究其他预算时，须补齐同预算基线。
- **C：** 基座和视觉编码器冻结，基线为4-bit NF4、语言q/v投影rank-8 LoRA。两个目标从同一份`data/reference_full/sft_pairwise.jsonl`的1,248对片段构造：pointwise共2,496条，pairwise共1,248条。数据生成种子固定2026，数据文件不随训练种子改变。
- C的micro-batch为1；pointwise梯度累积8次，pairwise累积4次，每步均处理8个候选片段。每次训练936步，在312、624、936步评价dev，三个检查点来自同一次训练。C1与对应C0保持相同片段曝光预算；改变采样时记录覆盖、重复和实际处理量。数据构造与预算细节见[实现与实验指南](学生作业说明.md)。

能复用组件关闭对照时，最低训练量为**A九次＋C九次**；不能复用的训练消融另按三个种子运行。BF16 LoRA等扩展为选做，不替代两种QLoRA必做目标。

### 选择与评价

1. A每个种子选该次dev mAP最高的检查点，并列取较早轮次；再按三种子的dev均值选择方法。C按三种子的dev平均mAP选择方法和共同预算，并列取较早预算。
2. 冻结方法、代码、配置、权重和数据哈希。用各任务选定方案的三个种子分别生成全部final 300条预测，C另生成匹配的零样本预测。预测列入实验记录，final指标统一评测。各项训练消融在dev上评分。
3. 报告mAP（tIoU 0.50—0.95、间隔0.05）、R@1@0.5、R@1@0.7及三种子的均值、样本标准差（`ddof=1`）、同种子“改进−基线”差值。A另报告Query Hit@3和GT Coverage@3，诊断候选覆盖。三次重复不自动证明统计显著。
4. C微调前后必须使用相同候选、提示和评分规则；改推理规则时须补匹配零样本。不能用C减去本组A解释重排收益，不能用成对微调减去逐候选零样本解释微调收益。
5. 不挑最好种子，不删除失败、回退或跳过的查询。保留日志、修复后重跑；最终评价须完整成功。

## 6 提交什么

只提交**模型、实验记录、汇报PPT**三类材料，不另交独立书面报告。

### 模型

- **A模型组：** 最终选定方法的3个种子权重、配置、自主实现代码和加载/评测命令。
- **C模型组：** 最终选定方法的3个种子LoRA适配器、匹配基础权重一份、配置、分词器/处理器、提示、自主实现代码和加载/评测命令。基础权重也用于复现零样本对照。

两个微调目标都要做实验，但最终模型只提交dev选定方案的三个种子。其他训练方案保留实验记录，不必提交全部消融权重。

### 实验记录

提交日志、逐查询预测JSONL、评分JSON和汇总表，至少包含：

| 记录项 | 具体内容 |
| --- | --- |
| 本组实现 | 研究假设、参考来源、代码位置、启用/关闭命令、每个对照改变了什么 |
| 数据与配置 | 划分及哈希、候选/样本来源与数量、种子、模型版本、帧数、像素预算、GPU与环境 |
| 训练过程 | A每轮损失、每5轮的dev指标；C训练损失、312/624/936步dev指标、采样/加权统计、实际曝光量与视觉token、参数更新和重载证据；选中检查点 |
| 预测与指标 | 每个qid的预测区间、分数和排序。提交dev评分、逐种子值、均值、标准差、配对差值，以及冻结后的final预测。确定性零样本填单次值 |
| 成本与异常 | 训练/推理耗时、显存峰值及统计口径、调用数、模型参数量与权重大小；失败qid、原因及修复情况，无失败写0 |

填写格式见[实验记录与PPT素材模板](实验报告模板.md)。

### PPT汇报

讲清两个任务的数据流、两个模块的实现与基线区别、对照结果和资源成本。至少分析三类错误，展示至少3组微调前后案例，包含未改善或退化案例；若未观察到，说明检查范围。列明4人分工、参考来源和AI辅助使用范围。

## 7 评分

| 项目 | 分值 | 规则 |
| --- | ---: | --- |
| A/C两项任务的平均排名 | 40 | 两榜均按三个种子的final mAP均值排名，名次等权平均 |
| 实验完整度 | 30 | 每个任务15分：基线与有效运行3分、自主实现6分、对照与记录6分 |
| PPT汇报 | 30 | 方案与实现10分、结果与对照10分、案例与结论10分 |

全班N组，名次为`r_A、r_C`，平均名次`r_avg=(r_A+r_C)/2`；排名分为`40×(N+1-r_avg)/N`，保留两位小数。指标均值按评分JSON计算，排序前不额外四舍五入，并列取平均名次。缺交、无法加载、缺少种子或未完成评价，该榜记`N+1`；零样本不单独排名。

各种子分别评价后取指标均值，不平均权重、不集成预测。某任务没有自主实现，其完整度最高9分。方法未提升不直接扣除实现、实验和汇报的相应分数，但须有完整证据和合理分析。
